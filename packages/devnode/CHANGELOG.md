# @webevm/devnode

## 0.2.0

### Minor Changes

- 05431da: `wrapDevNode` (and so `createDevNode`) forwards webevm's new `onConsoleLog` member to the wrapped node, so a dev node created with `consoleLog` delivers Solidity `console.log` entries to its subscribers as the node does.

### Patch Changes

- d679522: The README documents that `createDevNode` passes webevm's `consoleLog` option to the node it creates and that `onConsoleLog` on a dev node is the node's own: a subscriber receives the entries of the transactions and reads that go through the dev node, a dev account's `eth_sendTransaction` included, and on a node without console logging it throws the node's own error.

## 0.1.0

### Minor Changes

- d7ba813: **`toAllocs(dump)`: a webevm dump as the genesis alloc forge's `vm.loadAllocs` accepts**, so a `forge test` loads a deployment made on a dev node instead of replaying it. The result is `{address: {nonce, balance, code, storage}}`, nonces and balances as hex quantities (decoded from each account's RLP), code as hex, storage keyed by 32-byte slots with values padded to 32 bytes; every account in the dump is exported, the funded dev accounts included, and the storage root and code hash are dropped (forge recomputes both). It is a pure function of the dump, so it runs in Node as in a browser, on any dump (persisted ones and `senderMode: 'trusted'` chains included), and throws on a malformed one, naming the address and field. A manual script, `scripts/forge-load-allocs.mjs`, runs a real `forge test` against an export; it passed under forge 1.7.1.
- 2cc52b7: **New package: `@webevm/devnode`, dev accounts for webevm, funded at genesis.** `createDevNode(options)` creates a webevm node (every `createNode` option is accepted) whose `eth_accounts` answers with anvil's and Hardhat's ten default test accounts (the standard test mnemonic, `m/44'/60'/0'/0/i`), each holding 10,000 ETH at block 0, so index-declared accounts resolve to the same addresses as on those nodes. The accounts are configurable as `{mnemonic, count, path, initialIndex}`, a count, or a list of private keys; `balance` sets their genesis balance, `fund: false` funds none, and `fundAccounts` funds extra addresses (anvil's `--fund-accounts`), all merged into webevm's `initialBalances` with the caller's own entries winning. A chain restored by `loadState` or persistence keeps its own balances. `wrapDevNode(node, {accounts})` wraps a node that already exists and funds nothing; `devAccountBalances(options)` returns the `initialBalances` the same options would fund, for a node created elsewhere. The result is a `SlimNode`: every method it does not implement reaches the node unchanged (its errors, `-32601` included), `serveOn` serves the dev node's own `request`, and `dispose` closes the ports it served before disposing the node. `webevm` (`>=0.9.1`) is a peer dependency. Sending, signing, impersonation and an alloc export come in later releases.
- 67fcccc: **Impersonation, opt-in: `hardhat_impersonateAccount` / `hardhat_stopImpersonatingAccount` and their `anvil_` names.** With the new `impersonation: true` option, the four methods maintain a set of impersonated addresses (each returns `null`, as anvil answers them), and `eth_sendTransaction` from one is filled as a dev account's is, given a fabricated signature unique per sender (a fixed low `s`, an `r` derived from the address, so two senders' otherwise identical transactions get two hashes), and sent through webevm's `evm_sendRawTransactionAs`, executing as that address on either engine. The option needs a `senderMode: 'trusted'` node: `createDevNode({impersonation: true})` creates one and refuses an explicit `senderMode: 'recover'`; `wrapDevNode(node, {impersonation: true})` throws at once on any other node. While off (the default), the four methods answer `-32601` naming the option. Every signing method refuses an impersonated address with `4100` (no key is held for it); a dev account that is also impersonated still signs and sends with its key. The `4100` refusal of an unknown `from` now names `hardhat_impersonateAccount` (or `anvil_impersonateAccount`) for that address, or the option while it is off. A dump holding impersonated transactions is not replayable on a `'recover'` node.
- a85eb93: **`eth_sendTransaction` from dev accounts.** A request whose `from` is a dev account is filled, signed with that account's key and submitted, and its hash returned. Only what the request leaves out is filled: the nonce from the pending nonce, `gas` from `eth_estimateGas` on the same request, the fees from the node's fee market as `eth_fillTransaction` fills them. Nothing it names is dropped: a `gasPrice` sends type 0 (type 1 with an `accessList`), an `authorizationList` type 4, anything else type 2 carrying any `accessList`, an explicit `type` is honoured, and a request that cannot be sent as named (for instance `gasPrice` with EIP-1559 fees, or a `chainId` that is not the node's) is refused with `-32602`. On a `senderMode: 'trusted'` node the transaction goes through `evm_sendRawTransactionAs` with its real signature, on a `'recover'` node through `eth_sendRawTransaction`, so either chain's transactions replay on any node. Sends run one at a time, so concurrent sends from one account get consecutive nonces. A `from` the layer holds no key for is refused with `4100`, naming the remedies, and moves nothing. New dependency: `@ethereumjs/common`.
- f9556bb: **Dev accounts sign: `eth_signTransaction`, `personal_sign`, `eth_sign` and `eth_signTypedData_v4`.** `eth_signTransaction` fills and signs exactly as `eth_sendTransaction` does (same types, same refusals) and returns the raw signed transaction as hex without sending it. `personal_sign [message, address]` and `eth_sign [address, message]` (MetaMask's and geth's orders) sign the EIP-191 personal message; `personal_sign` reads a non-hex message as UTF-8 text, as MetaMask does, and `eth_sign` never signs a raw hash. `eth_signTypedData_v4 [address, typedData]` (an object or its JSON text) signs the EIP-712 digest, computed by the package's own encoder (nested structs, fixed and dynamic arrays, every atomic type; a missing `EIP712Domain` type is derived from the domain, as viem derives it). Signatures are 65-byte `r ‖ s ‖ v`, deterministic and low-`s`, identical to viem's local accounts' on the same key. An address the node holds no key for is refused with `4100`; a malformed request with `-32602`, naming what is wrong.
- 6cb7166: **The dev node in a Web Worker, both ways.** With the keys on the MAIN thread: `wrapDevNode(await createWorkerNode({worker, initialBalances: devAccountBalances({accounts})}), {accounts})` runs the EVM in the worker and answers the accounts, sends and signatures on the main thread. With the keys IN the worker: the new `@webevm/devnode/worker-host` entry exports `exposeDevNode({createEngine, accounts, balance, fund, fundAccounts, impersonation})`, the whole of a worker module; it hands webevm's worker host a node factory, so each `createWorkerNode()` (webevm's own client, unchanged) creates a dev node funded at genesis inside the worker, every `SlimNode` member crosses the boundary through webevm's single proxy, an `RpcError` the layer raises (`4100`, `-32602`) reaches the main thread with its `code`, and no key or mnemonic is ever sent to the main thread. The main thread's options (its `initialBalances` included, which still win over the dev funding) pass through as for any worker node. A bad mnemonic, key, count or `balance` never throws at module scope: it is logged in the worker at once and `createWorkerNode()` rejects with the same message, never a hang. `createDevNodeWorkerApi(options)` returns the same api without exposing it. `comlink` is an optional peer dependency (needed only for `/worker-host`, as in webevm). **The `webevm` peer minimum is now `>=0.10.0`**, the release whose `exposeNode` takes a node factory: on an older webevm that option would be ignored silently and the worker would run a plain node with no dev accounts. The README documents both recipes, including that a main-thread layer over a worker proxy serves its ports from the main thread (giving up `serveOn`'s worker-to-worker path) while the in-worker one keeps it.

### Patch Changes

- 223e452: **The core's cheats and snapshots are proven to reach the node through a dev node.** `hardhat_setBalance` / `hardhat_setNonce` / `hardhat_setCode` / `hardhat_setStorageAt` and their `anvil_` names, `evm_mine`, `anvil_mine` / `hardhat_mine`, and `evm_snapshot` / `evm_revert` (and `anvil_snapshot` / `anvil_revert`) answer through a dev node exactly as on the bare node, on both engines, now that webevm's core serves them; the dev node forwards them and implements none. A revert also rolls back what the dev node reads, so a dev account that sent inside a snapshot's window sends again at the earlier nonce. No behaviour change: a new test file and a README note.
