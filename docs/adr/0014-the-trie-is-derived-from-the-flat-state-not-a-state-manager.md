# The trie is derived from the flat state, not a state manager

> **Renamed 2026-09-28** (`rename-statemode-to-computestateroot`): the `stateMode: 'none' | 'trie'` option is now `computeStateRoot: boolean` (default `false`), with no alias; `'trie'` below is `computeStateRoot: true` and `'none'` is a node without it. The decision recorded here is unchanged; the rename is what it made honest, since once every node runs on the flat state the option no longer selects a mode, only whether a root is computed.

`stateMode:'trie'` used to mean a different state manager (`MerkleStateManager`) under the whole node, and that made it a different node: revm could not run in it (no synchronous reads, ADR 0005), its `dumpState` carried no storage, its touched-account tracking missed accounts changed by an internal call that emitted no log, `stateHistory` had to refuse it, and a creation over a storage-only account failed there and succeeded everywhere else. **We decided that every node runs on ONE state, the flat `OverlayStorageStateManager`, and that trie mode additionally keeps a Merkle-Patricia trie DERIVED from it** (`src/derived-trie.ts`): an account trie keyed by `keccak(address)` and one storage trie per account keyed by `keccak(slot)`, each account's `storageRoot` taken from its storage trie when the account is written. The trie is built once from the whole flat state (at construction, after the genesis baselines, and at the end of `loadState`) and kept current from the per-block change set of ADR 0013's seam, used only as a list of keys whose values are re-read from the flat state. The root is computed at the end of each mined block, before the block is stored, and by `getStateRoot()` for cheats since the head; both run inside the serialisation point with no checkpoint open. Execution never reads the trie, so it may be async and costs no opcode anything, which is what lets revm run in trie mode: ADR 0010 anticipated exactly this ("a state root computed OUTSIDE revm over the authoritative state stays reachable"). Spec: `work/specs/tasked/trie-mode-derives-its-root-from-the-flat-state.md`; task: `trie-derived-from-the-flat-state`.

**Storage-only creation collisions follow the reference spec, on every node.** A creation over a zero-nonce, code-less account that holds storage SUCCEEDS and WIPES the storage (EIP-684 plus the Yellow Paper, as execution-specs PR #3508 now specifies); a nonce or code at the target is still a collision. That is not EIP-7610 (a collision on storage too), which is still Last Call, which the reference spec went against, and whose shape mainnet is retiring by bumping those accounts' nonces (EIP-8253) rather than by a storage check. `'none'` mode and revm already behaved this way; trie mode was the outlier only because `MerkleStateManager`'s real `storageRoot` fed `@ethereumjs/evm`'s EIP-7610 guard, and it now runs on the flat state, whose accounts never carry a real `storageRoot`. Decided with the user on 2026-09-28, reversing the spec's launch decision ("EIP-7610 everywhere") after the spike `docs/spikes/revm-eip-7610-storage-collision/`. Source: `work/notes/findings/storage-only-creation-collisions-are-not-refused-by-the-reference-spec.md`.

## Considered Options

- **Keep `MerkleStateManager` and give revm a synchronous view of it.** Rejected in ADR 0005 already (a worker with `SharedArrayBuffer` and `Atomics.wait`, a second copy of state, cross-origin isolation), and it would still leave the dump, the touched-account gap and history to be solved twice.
- **Derive the root by walking the whole flat state per block.** Rejected: O(state) per block, the per-unit-of-work whole-state cost ADR 0009 removed for checkpoints. Applying the change set is O(what the block changed).
- **Build the trie from change sets alone.** Rejected: the genesis baselines and a loaded state are deliberately in no change set (they are block 0, or a baseline), so such a trie would omit them and every root would be wrong. Hence one full build at construction and after a load.
- **Retain old trie nodes** (so old roots stay readable). Rejected: history is the undo log (ADR 0013), a root alone answers nothing, and keeping every node is the archive-node route. Each trie is pruned (`useNodePruning`, one in-memory database per trie), so memory follows the live state.
- **Make every node refuse storage-only collisions (EIP-7610).** The spec's launch decision, reversed with the evidence above. It would also have needed revm to see storage it is never handed, or the store to misrepresent such an account.

## Consequences

- One behaviour per node whatever the mode: dumps carry storage in trie mode (and the trie is never serialised), revm and `stateHistory` work in it, and the node's own `touchedAccounts` set is gone.
- A trie-mode node records change sets whether or not `stateHistory` is on (the trie is their consumer); a `'none'` node without history still records nothing and creates no trie at all.
- The permanent root oracles are outside the node: the GeneralStateTests post-state roots (now also with revm) and the conformance battery's trie-backed `@ethereumjs/vm` reference (now also with revm, in both modes). The transitional differential against the old `MerkleStateManager` path was run while this landed and deleted with it; its script and output are `docs/spikes/trie-derived-from-the-flat-state/`.
- A trie-mode dump written before this change carries no storage (it was documented as unsuitable for persistence). Loading one yields the state it describes, storage still missing, so the roots derived from it are not the ones its block headers carry. No compatibility path was built for it.
- Nothing may write a real `storageRoot` into the flat state's accounts: `@ethereumjs/evm` would read it and refuse storage-only creations again, for that account only.
- Supersedes ADR 0005's section "`stateMode:'trie'` is a no" (amended there) and ADR 0013's refusal of `stateHistory` with trie mode.
