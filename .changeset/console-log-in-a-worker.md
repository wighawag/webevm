Solidity `console.log` in a Worker: the worker module enables it with `exposeNode({createConsoleLog: () => consoleLog()})` (also on `createNodeWorkerApi`), a factory called once per node on the worker thread whose result is merged into the main thread's options as `consoleLog`, exactly as `createEngine`'s engine is (a `createNode` factory receives it in its options). The default sink prints in the worker's console and a custom `onLog` runs on the worker; the main thread subscribes with `onConsoleLog(cb)` on the `createWorkerNode()` node, which crosses comlink as `onNewHead` does and receives the same entries as a main-thread node. `onConsoleLog` now works on any worker node whose node logs (including one a `createNode` factory enabled by itself) and still throws synchronously, now naming `createConsoleLog`, on one that does not. A `createConsoleLog` that is not a function is refused as a value (logged by the worker, and `createWorkerNode()` rejects with the same text); one that throws makes `createWorkerNode()` reject with its message. `WorkerNodeOptions.consoleLog` is typed `never` and `createWorkerNode({consoleLog})` is refused at runtime with a message pointing at `createConsoleLog`, instead of failing with a `DataCloneError` (TypeScript code that spreads a whole `NodeOptions` into `createWorkerNode()` must now omit `consoleLog`, as it already omits `engine`). The worker's `createNode()` result carries one extra plain value, `consoleLogEnabled`, beside the node's members.
