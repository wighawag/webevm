'webevm': patch
---

**A worker-hosted node now rejects with the same `RpcError` as a main-thread node.** Through `createWorkerNode` (and a worker module calling `exposeNode`), every `RpcError` the node raised used to reach the main thread with only its message: comlink carries a thrown `Error` as `{message, name, stack}`, so `code` was `undefined` and `data` was gone. That covered `-32000` refusals, `-32601`, `-32602`, `-32004` from `getStateRoot()`, and `3 execution reverted`, whose `data` is the revert payload viem decodes into a custom error, so a viem client behaved differently in a Worker. Now the error keeps its `code`, `message` and `data`, and is a real `RpcError` (`instanceof RpcError`, `name === 'RpcError'`) on the main thread, on every method of the node, matching what a `serveOn` port already delivered. Other errors (a plain `Error`, the misused-`createEngine` refusal) arrive as before. No comlink global state is changed. If you `wrap()` the worker-host api yourself instead of using `createWorkerNode`, an `RpcError` now rejects as a plain `{webevmRpcError: true, name, code, message, data, stack}` object rather than an `Error` carrying only the message.
