**The state cheats answer under Hardhat's and anvil's names too: `hardhat_setBalance`, `hardhat_setNonce`, `hardhat_setCode`, `hardhat_setStorageAt` and the same four as `anvil_*`.** Each has exactly the effect of the `evm_*` cheat it aliases, on both engines (the state root, the next block, the `stateHistory` change set and persistence included), so tooling written against Hardhat or anvil sets state on webevm unchanged: viem's `createTestClient` in `hardhat` and `anvil` mode drives `setBalance`, `setNonce`, `setCode` and `setStorageAt`, and rocketh's `fundImpersonatedAccounts` reaches `hardhat_setBalance`. They return what anvil returns under both names (`null` for balance, nonce and code, `true` for storage; Hardhat answers `true` for all four), and validate their parameters where Hardhat and anvil agree, refusing anything else with `-32602`: notably a storage value must be exactly 32 bytes, where `evm_setStorageAt` pads a shorter one. A nonce lower than the account's is accepted, as on anvil (Hardhat refuses it). The `evm_*` names are unchanged. The default entry grows by the aliases' validators and refusal messages, re-pinned in the bundle-size gate.
