New subpath `webevm/console-log`, exporting `consoleLog(options?)`: the object the node's upcoming `consoleLog` option takes (it is not wired into `createNode` yet). It decodes the calldata of Hardhat `hardhat/console.sol` and forge-std `console.sol` / `console2.sol` calls (every `log` / `logUint` / `logInt` / `logString` / `logBool` / `logAddress` / `logBytes` / `logBytesN` overload, plus the legacy `uint` / `int` selectors old Hardhat versions compiled against) into `{args, message}`, with a hand-written ABI decoder and a browser-safe formatter that prints the line Hardhat prints (format strings with `%s`, `%d`, `%i`, `%o`, `%O`, `%%`, integers in full decimal, addresses checksummed); malformed calldata decodes to nothing. By default every entry is printed through `console.log` with a `[webevm console.log]` prefix, and `consoleLog({onLog})` replaces that. The entry types (`ConsoleLogEntry` with `source` and, for a mined transaction, `txHash`, `blockNumber`, `blockHash`, `txIndex`) are exported from the subpath. forge-std's `console.table` is not decoded. The default entry is unchanged. See `docs/adr/0018-console-log-is-observed-never-answered.md`.
