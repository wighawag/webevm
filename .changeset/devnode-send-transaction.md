**`eth_sendTransaction` from dev accounts.** A request whose `from` is a dev account is filled, signed with that account's key and submitted, and its hash returned. Only what the request leaves out is filled: the nonce from the pending nonce, `gas` from `eth_estimateGas` on the same request, the fees from the node's fee market as `eth_fillTransaction` fills them. Nothing it names is dropped: a `gasPrice` sends type 0 (type 1 with an `accessList`), an `authorizationList` type 4, anything else type 2 carrying any `accessList`, an explicit `type` is honoured, and a request that cannot be sent as named (for instance `gasPrice` with EIP-1559 fees, or a `chainId` that is not the node's) is refused with `-32602`. On a `senderMode: 'trusted'` node the transaction goes through `evm_sendRawTransactionAs` with its real signature, on a `'recover'` node through `eth_sendRawTransaction`, so either chain's transactions replay on any node. Sends run one at a time, so concurrent sends from one account get consecutive nonces. A `from` the layer holds no key for is refused with `4100`, naming the remedies, and moves nothing. New dependency: `@ethereumjs/common`.
