Solidity `console.log` support: `createNode({consoleLog: consoleLog()})`, with `consoleLog` from `webevm/console-log`, delivers every Hardhat `console.sol` / forge-std `console.sol` / `console2.sol` call made by a mined transaction (automine, `mine()`, `evm_mine`, interval mining) or an `eth_call` to the sink (by default `console.log`, prefixed `[webevm console.log]`; `consoleLog({onLog})` replaces it) and to the new `node.onConsoleLog(cb) => unsubscribe`, as a structured entry `{args, message, source}` (a `'transaction'` entry also carries `txHash`, `blockNumber`, `blockHash`, `txIndex`). Calls inside a reverting sub-call, a reverting transaction or a reverting `eth_call` are delivered too; `eth_estimateGas` and `eth_fillTransaction` deliver nothing. Execution is observed, never changed: receipts, gas, return data and the state root are identical with it on and off. Entries are delivered after the engine returns (a block's once it is stored, in transaction order, before the `onNewHead` emit; a read's before it returns or throws); the sink and subscribers are never awaited, and a throw or rejection from one is reported through `console.error` and fails nothing. Nothing is persisted. An engine that does not declare `recordsCalls` (today `webevm/revm`, until it moves to revm-wasm 0.6.0) is refused at construction; on a node without the option, and on a `createWorkerNode()` node for now, `onConsoleLog` throws. A `consoleLog` option that is not the object `consoleLog()` returns is refused at construction. The default entry grows by 2.2 KB raw (the decoder stays in the subpath). See `docs/adr/0018-console-log-is-observed-never-answered.md`.
