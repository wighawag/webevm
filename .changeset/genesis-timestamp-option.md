**New `genesisTimestamp` option pins the genesis block's timestamp.** `createNode({genesisTimestamp: 1700000000n})` stamps block 0 with that value (a `bigint`, seconds since the epoch, the unit of `blockEnv.timestamp`); `eth_getBlockByNumber('0x0')` reports it and a contract reading `TIMESTAMP` at block 0 sees it, on both engines. Without it, block 0 keeps the wall clock as before, which is why two nodes running the same chain but created in different seconds used to hash every block differently: with `genesisTimestamp` set (and `blockEnv.timestamp` pinning the mined blocks) they now produce byte-identical `dumpState`s. It moves only block 0, independently of `blockEnv` (which still leaves genesis's timestamp alone), and mined blocks keep the wall clock even when the genesis timestamp is in the future. A state loaded with `loadState` (or restored by IndexedDB persistence) keeps its own block 0. It crosses `createWorkerNode` like every other option. A value that is not a non-negative `bigint` (a number, a string, a negative bigint) throws at construction, naming the option. The default entry grows by 0.3 KB raw (0.1 KB gzip) for that validation and its message.
