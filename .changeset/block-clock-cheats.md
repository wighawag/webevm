**Time cheats, under anvil's names and wire shapes: `evm_setNextBlockTimestamp`, `evm_increaseTime`, `evm_mine`, `anvil_mine` (alias `hardhat_mine`) and `anvil_setBlockTimestampInterval` / `anvil_removeBlockTimestampInterval`.** A local chain can now be moved through time the way anvil, hardhat and ganache move theirs, which a contract measuring elapsed time (interest, vesting, oracles, TWAPs) needs in order to be exercised at all, and viem's test actions drive it unchanged: `createTestClient({mode: 'anvil', transport: custom(node)})`'s `setNextBlockTimestamp`, `increaseTime`, `mine`, `setBlockTimestampInterval` and `removeBlockTimestampInterval` all work (the hardhat and ganache modes' time actions too). A next timestamp stamps the next block (later than the head's, else `-32000`) and the clock carries on from it; `evm_increaseTime` returns the total offset as a JSON number; `evm_mine` takes `[]`, `[timestamp]` or `[{timestamp, blocks}]` and returns `"0x0"`; `anvil_mine [blocks, interval]` returns `null`; an interval makes every block its parent's timestamp plus that many seconds, so the same chain hashes identically however fast it ran. Every transaction's `TIMESTAMP` reads the stamped value on both engines. **Nothing changes for a node that issues none of them**: mined blocks are stamped with `blockEnv.timestamp` or the wall clock exactly as before. The clock is node state, not chain state: it is not in `dumpState`, and `loadState` drops a pending next timestamp. The default entry grows 1.6 KB raw / 0.5 KB gzip (the clock and its refusal messages; no import added), re-pinned in the bundle-size gate.
