**Snapshots: `evm_snapshot` / `evm_revert`, and anvil's `anvil_snapshot` / `anvil_revert`.** `evm_snapshot` returns an id for the chain as it stands and `evm_revert [id]` puts it back on both engines: state, blocks and their hashes, receipts, `eth_getTransactionByHash`, logs, `getStateRoot()`, pinned reads in the `stateHistory` window, and the transactions waiting to be mined; the chain then continues exactly as one that never ran the reverted work. The semantics are Hardhat's and anvil's: ids are quantities, `"0x0"` first as on anvil (Hardhat starts at `"0x1"`) and never reissued; a revert returns `true`, or `false` for an id the node does not hold; and reverting consumes that snapshot and every later one. The clock follows anvil: a pending next timestamp and the `evm_increaseTime` offset are restored, the interval is kept. With persistence, a revert saves the reverted chain. viem's `createTestClient` `snapshot` / `revert` work unchanged in every mode. A snapshot is the node's own `dumpState()` and a revert its `loadState()`, so both cost O(state): measured and stated in the README (a revert with `computeStateRoot` rebuilds the derived trie and is the expensive case). The default entry grows by 1.2 KB, re-pinned in the bundle-size gate.
