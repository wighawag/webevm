# Decisions made while building `snapshots-in-the-core` (2026-11-20)

The full reasoning, with the Hardhat (EDR ee0dece6) and anvil (foundry 0ccc114d) sources cited, is the JSDoc at `takeSnapshot` in `packages/webevm/src/node.ts`. One entry per choice a reviewer might be surprised by:

- **Ids are anvil's: `"0x0"` first, one counter for the `evm_*` and `anvil_*` names, never reissued.** Alternative: Hardhat's (and ganache's) `"0x1"` first. Chosen because ADR 0016 makes anvil the reference where the two differ, and anvil serves both names from one counter. Touches any caller that hardcodes an id (rare; viem passes back what it was given). Pinned in `test/snapshots-expected.ts`.
- **The clock: a pending next timestamp and the offset are restored; the interval is kept.** That is anvil's `TimeSnapshot` exactly. Hardhat also restores both (it has no interval) but adds the wall-clock seconds elapsed since the snapshot to the offset, so its clock rewinds to the snapshot moment; not done here (anvil is the reference, and on a pinned `blockEnv.timestamp` there is no wall time to compensate). Touches ADR 0016's clock; `loadState` still drops a pending next timestamp, unchanged.
- **A snapshot is more than a dump: it keeps the undo log UNFOLDED with its open record, the pending transactions and the clock.** The task proposed a bare `dumpState()`; that alone would fold cheats issued after the head into the head (as a dump and load do), so after the next block the old head would read the cheats where a never-reverted node does not. The battery's control-node comparison catches it. Pending transactions are restored because both Hardhat and anvil restore their pools.
- **A revert empties the flat state before `loadState`** (new internal `OverlayStorageStateManager.clearState`), because `loadState` writes over what is there and removes nothing. Also added `replaceChangeSet` to put the open record back. Both internal; no option exposes them.
- **A revert emits no `newHeads`; snapshots survive a `loadState`; snapshots are not persisted.** Alternatives: emit the restored head (anvil emits removed logs to filters, which this node has none of), or drop snapshots on load. Kept minimal; each is easy to change later.
- **A successful revert persists** (the `persistence.save()` hook runs after it, like a mine); a refused one and a snapshot do not.
