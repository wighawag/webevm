---
title: decisions made while making a worker node keep the RpcError code and data
date: 2026-09-28
status: open
---

In-scope decisions from `a-worker-node-keeps-the-rpc-error-code-and-data`, one entry each, for the reviewer to ratify or reverse. The full rationale for decision 1 is the module JSDoc of `packages/webevm/src/worker-rpc-error.ts`.

1. **A third shape, neither of the two the task proposed: the host THROWS a plain object in place of an `RpcError`.** comlink's built-in `throw` handler passes a thrown non-`Error` value through structured clone unchanged and rethrows it as-is (`comlink@4.4.2`, `throwTransferHandler`, `isError: false` branch), so `{webevmRpcError: true, name: 'RpcError', code, message, data, stack}` crosses with every field and the client rebuilds a real `RpcError` from it. Touches no comlink global state (acceptance criterion 5 is met by the first branch, nothing is changed). Alternatives: a comlink transfer handler (rejected: `transferHandlers` is module-global, so it would change error handling for any other comlink use in the consumer's app); an `{ok}` / `{error}` envelope (rejected: it rewraps every SUCCESSFUL answer and changes every proxied method's wire return type, which would break the `Required<SlimNode>` typing the host proxy and client rely on, where the thrown object only touches the failure path). Touches: `src/worker-host.ts` (`nodeProxy`), `src/worker-client.ts`, the new `src/worker-rpc-error.ts`.
2. **Every async method of the proxy is wrapped, not only `request`**: `request`, `mine`, `dumpState`, `loadState`, `getStateRoot`, `serveOn`, `dispose`. `onNewHead` is not, because it is synchronous on the node and throws nothing. Wrapping a method that raises no `RpcError` today costs nothing and covers one that does later.
3. **Visible to a consumer who `wrap()`s the worker-host api directly** (not through `createWorkerNode`): an `RpcError` now rejects as the plain object above rather than an `Error` carrying only the message. `e.code`, `e.message` and `e.data` work on it; `e instanceof Error` does not. Recorded in the changeset and the JSDoc. Alternative: keep the thrown value an `Error` and smuggle the fields another way, which comlink's handler does not allow without a global handler (decision 1).
4. **An `RpcError` is recognised by class OR by shape** (`name === 'RpcError'` plus a numeric `code`), so one built from another copy of the package (a consumer's engine bundling its own) still crosses whole. The name is required alongside the code because a `DOMException` also has a numeric `code`.
5. **The worker's stack is kept on the rebuilt `RpcError`**, as comlink does for a plain `Error`, since it is where the error was raised.
6. **`executeAll` in `test/helpers/historical-call.ts` now writes refusals as `ERROR <code> <message>`** (it wrote the message only), so every question in the transports test, not only the point reads and `eth_estimateGas`, compares the worker leg by code and message. Its other users compare its output node against node or check only the `ERROR` prefix, so they are unaffected.
7. **The README's Worker section gained a paragraph** ("Errors cross whole") stating the parity and the direct-`wrap()` shape, since the README claims the two kinds of node are interchangeable.
