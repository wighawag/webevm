# Decisions taken while building state-history-docs-and-worker

2026-09-28. In-scope choices made by task `state-history-docs-and-worker` that a reviewer may want to ratify or reverse. None changes the feature's architecture (ADR 0013), so no new ADR.

1. **Through `createWorkerNode`, refusals are compared by MESSAGE, not code.** comlink drops a thrown Error's `code` (observation `comlink-drops-the-rpc-error-code.md`), so the `worker` transport receives every refusal with `code === undefined`. The transport test (`packages/webevm/test/helpers/state-history-transports.ts`) accepts a refusal there when its message equals the reference's and COUNTS the lost codes (`workerCodesLost`, 778 in a run); the two `serveOn` ports are compared by code and message. Alternative: fix the comlink error path in this task; rejected as out of scope (it affects every error on every method, not the history feature) and captured instead.
2. **The Worker leg runs the default engine only.** `createWorkerNode` cannot carry an engine, and the test's worker module exposes `createNodeWorkerApi()`, the same api `exposeNode` builds, which forwards the options object unchanged to `createNode` (with an engine added only when `createEngine` is given). A revm-in-a-worker run would add no transport coverage the history batteries do not already have per engine. Alternative: a second worker module with `createEngine: () => createRevmEngine(...)`.
3. **Block hashes are taken from each transport's own node.** Genesis is stamped with the wall clock, so two nodes running the same chain have different hashes; the `{blockHash}` questions use each node's hash for block K. Everything else (numbers, values, refusal texts) is compared verbatim.
4. **The window in the transport test (4) is smaller than the chain (10 blocks)**, so the beyond-the-window refusal is among the compared answers and proves the option reached the worker (a worker node without it refuses every block below the head with a different message).
5. **Costs measured under Node (V8), not in a browser.** `docs/spikes/bounded-state-history-cost/measure-state-history-cost.mjs` runs each memory configuration in a fresh child process and takes bytes per key from the difference between windows of 64 and 256 so one-off allocations cancel; `results.md` beside it records the output. The README quotes those figures and says they are V8 under Node. Alternative: a playwright benchmark; rejected because heap figures need `--expose-gc` and a fresh process per row, which the harness does not give.
6. **The cost is stated as two terms** (about 0.8 µs per DISTINCT key changed since K, about 0.03 µs per further record), not one "per key changed" figure, because the measurement shows the distinction matters by 25x: a game rewriting the same cells pays the small term, one writing new keys the large one.
7. **The README section was renamed**, so its anchor changed from `#state-reads-are-served-at-the-head-only` to `#state-reads-at-past-blocks-statehistory`; every link inside the README was repointed (a repo-wide search found no other reference). External links to the old anchor land at the top of the page.
8. **The unreleased `.changeset/pinned-reads-refuse-history.md` was edited** ("By default this node keeps only the state at its head", with a pointer to the new entry), per the forward-pointer asking the two changesets to read consistently. The new `.changeset/bounded-state-history.md` is the feature's one `minor` entry (point reads, historical `eth_call` / `eth_estimateGas`, persistence, transports, cost), as `state-history-point-reads` decision 1, `historical-eth-call` decision 10 and `state-history-persistence` decision 6 deferred it.
9. **The stale JSDoc on `NodeOptions.stateHistory`** (`packages/webevm/src/types.ts`, which still said `eth_call` / `eth_estimateGas` are served at the head only) now says they execute at K, mentions persistence and quotes the measured cost. Comment only: the bundle-size pin was not touched and `bundle size per backend` stays green.
10. **The README's `eth_estimateGas` table row had two em dashes**, rephrased because the row was edited anyway (the repo-wide cleanup of the older ones is not this task's).
