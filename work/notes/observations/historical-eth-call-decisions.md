# Decisions taken while building historical-eth-call

2026-09-28. In-scope choices made by task `historical-eth-call` that a reviewer may want to ratify or reverse. The architecture (an undo log over the flat state, reused as a state override for execution) is `docs/adr/0013-bounded-state-history-is-an-undo-log-over-the-flat-state.md`, which already names this task's mechanism, so no new ADR. Each entry names its code site in `packages/webevm/src/node.ts` unless stated.

1. **No BLOCKHASH read horizon.** The acceptance test was written and run first without one, and both engines already answer `BLOCKHASH(n)` with zero for `n >= NUMBER`, so running with K's stored `Block` is enough: `BLOCKHASH(K)` and `BLOCKHASH(K+1)` are zero at K, `BLOCKHASH(K-1)` is the real hash, and `BLOCKHASH(K)` at the head is the real hash (`test/historical-call-expected.ts`, both engines). Alternative: a node-level horizon consulted by `getBlockHash` / `mockBlockchain.getBlock`, reset in a `finally`; not built because nothing needed it. Site: the JSDoc of `evmCall`.
2. **One gate for all six state methods.** `requireHeadState` is gone; `eth_call` and `eth_estimateGas` now go through `historicalBlock` like the point reads, so the window, the refusal beyond it and `header not found` are one rule. Its JSDoc moved onto `historicalBlock` (it says it was `requireHeadState`). ADR 0013's mention of `requireHeadState` is left as the historical record; the one README pointer at it now names `historicalBlock` (the surrounding README section is `state-history-docs-and-worker`'s to rewrite).
3. **The override path is split into parse / apply / checkpoint** (`parseStateOverrides`, `applyStateEntry`, `withStateEntries`) around an INTERNAL `StateEntry`, and both the RPC overrides and K's state (`historicalEntries`) go through the one apply step, K's entries first so the caller's overrides land on top. "State entry" is a new internal name, deliberately not "override": an override is the RPC JSON a caller sends, an entry is an already-parsed write, and history is not an override the caller asked for. Not exported.
4. **The RPC override apply order changed** from account, code, storage to CODE, account, storage (then, for an absent entry only, emptied code and `deleteAccount`). Needed so a whole historical account written after `putCode` keeps K's `codeHash`, and so `putCode`'s account creation cannot resurrect an absent one. For the RPC fields (balance/nonce are a read-modify-write that re-reads the account `putCode` just wrote) the outcome is the same; `test/rpc-params.spec.ts` and its revm twin guard it in both state modes.
5. **An account absent at K is always written as emptied code plus `deleteAccount`**, as the task specifies. Consequence in one edge case: after a same-transaction CREATE then SELFDESTRUCT, `'none'` mode leaves the dead contract's code in the code map (backlog task `a-deleted-accounts-code-survives-in-none-mode-and-reload-resurrects-it`). If such an address is touched after K, a historical call at K sees no code (EXTCODESIZE 0) while the POINT read `eth_getCode` at K, and the default engine's EXTCODESIZE at the head, still see the leftover bytes. The historical call is the correct one; the others are that backlog bug. Site: `applyStateEntry`.
6. **The whole `eth_estimateGas` search runs inside ONE checkpoint holding K's state**, applied once, not per probe. Site: the `eth_estimateGas` case.
7. **`eth_estimateGas` at K still caps its search at the node's MINED block gas limit, not K's `gasLimit`**, because the number is for a transaction submitted now. Site: the cap comment in `estimateGas`.
8. **The earliest-wins union is built fresh** rather than with `mergeChangeSetOlderWins`, which consumes its second argument and would alias (then mutate) the sealed records. Site: `historicalEntries`.
9. **Test changes outside the new battery:** `test/state-history-expected.ts` now expects `eth_call` / `eth_estimateGas` inside the window to be SERVED (they were asserted refused with "head only"), and `test/helpers/state-history.ts` adds both to the beyond-the-window refusals; `keysOfDump` there is exported for the new battery's key universe.
10. **No changeset in this task**, for the reason `state-history-point-reads` gave (decision 1 of `work/notes/observations/state-history-point-reads-decisions.md`): `state-history-docs-and-worker` owns the feature's one `minor` changeset, and it should mention historical `eth_call` / `eth_estimateGas` too.
11. **The bundle-size pin is re-pinned** to 439.9 KB raw / 132.5 KB gzip (from 439.2 / 132.3), measured after `pnpm build`, with a history entry in `DEFAULT_ENTRY_BASELINE`'s comment in `packages/benchmarks/test/evm.spec.ts`.
