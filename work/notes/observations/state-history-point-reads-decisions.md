# Decisions taken while building state-history-point-reads

2026-09-28. In-scope choices made by task `state-history-point-reads` that a reviewer may want to ratify or reverse. The architectural one (an undo log over the flat state, with the rejected alternatives) is `docs/adr/0013-bounded-state-history-is-an-undo-log-over-the-flat-state.md`; the rest are listed here, each with its code site.

1. **No changeset in this task.** The `stateHistory` option becomes live here, but task `state-history-docs-and-worker` owns the feature's `minor` changeset (its acceptance criterion "A changeset exists"), and two changesets describing one feature would ship two release notes for it. Alternative: a changeset here too. Touches: that task. If this lands in a release before the docs task, the release notes omit the option.
2. **The below-the-head refusal changed wording on EVERY node, not only on one with history.** Without `stateHistory` it now names the oldest servable block (the head) and tells the caller to create the node with `stateHistory: {blocks: N}`. Code and the phrase `historical state not available` are unchanged, so `test/block-pinned-state.spec.ts` is untouched and green. Site: `beyondHistory` in `packages/webevm/src/node.ts`.
3. **`stateHistory: null` throws** (only `undefined` means off), per the task's "anything else throws". Site: `validateStateHistory` in `src/node.ts`.
4. **History restarts at the loaded head after `loadState`** (`historyFloor`), and the sealed log is cleared, until `state-history-persistence` carries it in the dump. That task's own acceptance ("an old dump loads with history starting at its head") matches. Site: `historyFloor` and the end of `loadState` in `src/node.ts`.
5. **A block mined under the number of the block it replaces (fixed `blockEnv.number`) is MERGED into that block's record, older value winning**, so the log stays bounded and reads below that number stay right. Alternative: key records by mining sequence. Site: `sealBlock` in `src/node.ts` (merge helper `mergeChangeSetOlderWins` in `src/state-manager.ts`, now shared with checkpoint commit).
6. **A number inside the window that names no block** (only possible when `blockEnv.number` jumps) is `-32000 header not found` for the point reads, rather than answered. Site: `historicalBlock` in `src/node.ts`.
7. **`eth_call` / `eth_estimateGas` below the head inside the window keep code `-32000` and the phrase `historical state not available`**, and say they are served at the head only while the four point reads are served in the window. Lifted by `historical-eth-call`. Site: `requireHeadState` in `src/node.ts`.
8. **Test-only surface:** the existing `changeSetsForTests` probe gained `sealedBlocks` (the memory-bound probe) rather than a second accessor; the change-set chain in `test/helpers/change-set.ts` is now exported (`runChangeSetChain`, `chainNodeOptions`) so the history differential drives the same write routes instead of a copy.
