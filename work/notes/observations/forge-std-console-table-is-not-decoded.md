# forge-std's `console.table` is not decoded by `webevm/console-log`

2026-11-24. Found while vendoring the console libraries for task `webevm-console-log-decodes-and-formats-console-calls`: forge-std `v1.17.0`'s `src/console.sol` (pinned under `packages/webevm/test/fixtures/console-log/`) has twelve `table(...)` functions taking ARRAYS (`table(uint256[])`, `table(string[],bool[])`, ...), which the spec `solidity-console-log` and ADR 0018 did not anticipate: both describe the decoder as covering `uint256`, `int256`, `bool`, `address`, `bytes1`..`bytes32`, `string` and `bytes` only. The task left them out of the selector table (a `table` call is an unknown selector, ignored), recorded in the header of `packages/webevm/src/console-log-decoder.ts`, and `packages/webevm/test/console-log.spec.ts` asserts the exclusion is exactly those twelve. Supporting them is additive (an array decoder plus a rendering of forge's table output, whose exact format would need checking against `forge test`) and would be its own task if a user asks. Also at this pin, `console2.sol` is only a re-export of `console.sol`.
