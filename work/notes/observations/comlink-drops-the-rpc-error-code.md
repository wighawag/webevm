# Through `createWorkerNode`, an RpcError arrives without its `code`

2026-09-28, noticed by task `state-history-docs-and-worker`. comlink's default throw handler serialises a thrown Error as `{message, name, stack}` only (`node_modules/comlink/dist/esm/comlink.mjs`, `throwTransferHandler`), so every `RpcError` a worker-hosted node raises reaches the main thread with `code === undefined`: `-32000 historical state not available`, `-32601`, `3 execution reverted` and the rest. The message survives. `serveOn` ports are NOT affected (`@eip-1193/over-port` carries `code`, `message` and `data`), so a worker-hosted node and a port it serves disagree on the code of the same refusal. The README's claim that the two kinds of node are interchangeable does not hold for error codes, and a viem client that branches on `code` behaves differently in a Worker. Likely fix: a comlink transfer handler (or a wrap in `src/worker-host.ts` / `src/worker-client.ts`) that carries `code` and `data`. `test/helpers/state-history-transports.ts` counts the lost codes (`workerCodesLost`) rather than asserting them, pending that fix.
